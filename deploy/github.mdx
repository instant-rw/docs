Connect a GitHub repository and Instant Cloud builds and deploys it every time you push to the production branch. You don't need a CI pipeline or a deploy script, and the version that's live keeps serving until the new one is ready.

## Connect GitHub

Instant reads your code through the Instant GitHub app. You install it once per GitHub account or organization, and choose which repositories it can see.

<Steps>
  <Step title="Start a new application">
    In the dashboard, open **Applications** and select **New application**.
  </Step>
  <Step title="Install the GitHub app">
    Under **Import a repository**, select **Connect GitHub**. GitHub asks where to install the app and which repositories to give it. You return to Instant when it's done.

    If you install it on a GitHub organization you don't own, an owner of that organization has to approve it first.
  </Step>
  <Step title="Pick the repository">
    Choose the account, search for the repository and select it. To give Instant access to more repositories later, select **Adjust GitHub access**.
  </Step>
</Steps>

## Set up the app

Before the first deploy, check the sections of the form:

- **Source**: the branch to deploy and, for a monorepo, the **Root directory** that holds the app.
- **Build**: the detected framework, and the build and start commands. Leave them empty to use what Instant detects. See [Builds](/deploy/builds).
- **Environment**: variables your app needs at build time and at runtime. See [Environment variables](/deploy/environment-variables).
- **Databases**: databases to connect, so their connection strings are added for you.
- **Run**: the region, the size and the number of replicas. The region can't be changed later.

Select **Deploy** to create the app and start the first deployment.

## Deploy on push

With **Deploy on push** turned on, which is the default, every push to the production branch starts a deployment. You can change the branch and turn this off in the app's **Settings** > **General**, under **Git**. A branch change applies from the next push.

If you push again while a deployment is still waiting in the queue, the newer push replaces it. Deployments of one app run one at a time.

You can always deploy the latest commit by hand with **Deploy** on the app's **Deployments** page, or with `instant deploy --git`.

## Monorepos

Several apps can come from the same repository. Create one app per service and give each its own **Root directory**, such as `apps/web` and `apps/api`. Every push to the branch deploys each of them.

Instant detects the framework inside each root directory.

## Pull request previews

Preview deployments for pull requests are not available yet. The **Previews** tab on the Deployments page lists your repository's pull requests in the meantime.

## Disconnect a repository

If you remove the Instant GitHub app from an account on GitHub, apps using its repositories stop deploying on push. Apps that are already live keep running. To deploy without GitHub, see [Deploy without Git](/deploy/without-git).
