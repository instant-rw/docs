---
title: "Deploy a folder"
description: "Deploy the code on your computer with instant deploy, without pushing to GitHub."
---

`instant deploy` packs a folder, uploads it and builds it the way Instant builds a commit: it detects the framework and runs the build and start commands.

## Deploy

<Steps>
  <Step title="Sign in">
    Run `instant login`.
  </Step>
  <Step title="Run deploy in your project">
    ```sh
    cd my-project
    instant deploy
    ```

    The first time, the CLI offers to link an existing app or create a new one, and remembers the choice in `.instant/project.json`.
  </Step>
  <Step title="Follow the build">
    The CLI shows the build log and prints the app's URL when it is live. Use `--detach` to return right after the deployment starts.
  </Step>
</Steps>

To create the app first, run `instant apps create my-app --upload`, then `instant link my-app` in your folder.

Useful options: `instant deploy ./site --app my-site` deploys another folder to a named app, and `-m "fix header"` adds a note shown with the deployment.

## What is uploaded

The CLI packs the folder into a gzipped tarball. It leaves out:

- everything matched by `.gitignore` or `.instantignore`, in any folder, with the same syntax
- always: `.git`, `node_modules`, `.instant`, `.env`, `.env.*` (but not `.env.example`) and `.DS_Store`

Put large files or folders that the build does not need in `.instantignore`. Set secrets as [environment variables](/cli/overview) with `instant env set`, because `.env` files are never uploaded.

The packed size is limited to 100 MB. Over the limit, the CLI lists the largest files so you can ignore them.

## GitHub apps and upload apps

| | Upload app | GitHub app |
| --- | --- | --- |
| Created with | `instant apps create <name> --upload` | `instant apps create <name> --repo owner/repo`, or the dashboard |
| Deploys on every push | No | Yes |
| `instant deploy` | Uploads and deploys the folder | Uploads and deploys the folder, on top of the push deploys |
| `instant deploy --git` | Rebuilds the last upload | Deploys the head of the branch without uploading |

## Rollbacks and retention

Run `instant deployments` to list deployments and `instant rollback <deployment>` to deploy an earlier one again. For an uploaded deployment this rebuilds the stored folder.

Uploaded folders are kept for 30 days so rollbacks can rebuild them. The folder behind the app's running version is always kept. A deployment whose upload is older than 30 days can no longer be rolled back to.
