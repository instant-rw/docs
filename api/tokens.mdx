title: "API tokens"
description: "Create an Instant Cloud API token for CI, scripts and MCP clients that cannot sign in through a browser, use it with the CLI or the API, and revoke it."
---

An API token lets a script, a CI job or an MCP client use the CLI, the API or the MCP server without signing in through a browser.

## Create a token

<Steps>
  <Step title="Open Developer settings">
    In the dashboard, go to **Settings** > **Developer** and select **Create token**.
  </Step>
  <Step title="Set the name, access and expiry">
    Name the token after where it will be used, such as `github-actions`. Choose **Full access** or **Read only**, and an expiry of 7, 30, 90 or 365 days, or never.
  </Step>
  <Step title="Copy the token">
    The token starts with `inst_` and is shown only once. Store it as a secret right away.
  </Step>
</Steps>

## What a token can do

A token acts as the person who created it, in the organization it was created in. **Full access** can make changes; **Read only** can only read. Like an [MCP connection](/agents/overview), a token can never delete apps, databases, buckets or domains, restore backups, change the plan, make payments, or manage members and tokens.

A token stops working when it expires, when it is revoked, or when its creator leaves the organization.

## Use a token

With the CLI, set `INSTANT_TOKEN`. No `instant login` is needed.

```sh
INSTANT_TOKEN=inst_… instant deploy --app my-app --yes
```

With the API or the MCP server, send it as a bearer token:

```sh
curl https://api.instant.rw/v1/apps \
  -H "Authorization: Bearer inst_…"
```

`instant login --token inst_…` stores a token on your own computer instead.

## Use a token in CI

To deploy from GitHub Actions or another CI service, store the token as a secret named `INSTANT_TOKEN` and run `instant deploy`. [Scripts and CI](/cli/scripts-and-ci) has a complete GitHub Actions workflow.

## Revoke a token

In **Settings** > **Developer**, select **Revoke** next to the token. It stops working at once. Members can revoke their own tokens; owners and admins can revoke any token in the organization.
